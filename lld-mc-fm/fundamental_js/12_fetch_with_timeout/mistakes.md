1. fetch() does not block JavaScript execution. The network request is initiated immediately, and setTimeout() simply schedules a callback to run after a specified duration. Both operations proceed independently. If the fetch completes first, the timeout is cleared. If the timeout expires first, the AbortController aborts the fetch request. Thus, the timeout and the fetch are effectively racing against each other, and whichever completes first determines the outcome.

2. AbortController does not directly stop a network request by itself. Instead, it provides an AbortSignal, which acts like a notification mechanism. When APIs such as fetch receive this signal, they start listening to it while performing their work. If abort() is called on the controller, the signal changes its state to indicate that cancellation has been requested and sends out a notification. Any operation that is listening to this signal reacts accordingly. In the case of fetch, it stops the network request and rejects the promise with an AbortError. So, rather than forcibly stopping code execution, AbortController simply broadcasts a "please cancel" message, and the APIs that are listening decide how to handle that cancellation request.
